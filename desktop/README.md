# 치지직 데스크

치지직을 최대 네 화면으로 보고, 듣는 방송을 바꾸고, 방금 지나간 장면을 로컬 MP4로 저장하는 Windows 데스크톱 시제품입니다. 0.5.0에는 시청 모음, 즐겨찾기 이름 수정·상단 고정, 전체 보관 제어와 클립 제목·별표·필터·전체 검색을 추가했습니다. 채널별 키워드·채팅 급증 자동 클립, 수동 저장 길이 15·30·60초 선택과 통나무 자동 수령도 제공합니다. 기존 Python 채팅 봇과 별도로 실행됩니다.

**현재 방송별 저장 호환성을 확인 중인 시제품입니다.** 네이버 웹 로그인 세션을 녹화 요청에도 연결했으며, 사용자가 로그인 후 실제 방송에서 저장한 MP4 두 개의 영상과 음성을 FFmpeg로 끝까지 디코딩했습니다. 로그인 유무에 따라 키 접근을 허용·거부하는 테스트 영상의 저장과 영상/음성 디코딩도 통과했습니다.

같은 점검에서 **공개 생방송 두 개의 일반 화질(480p) 동시 재생**과 재생 시간 진행을 확인했습니다. 계정 로그인은 사용자가 성공을 확인했으며, 고화질 확장 프로그램은 지원하지 않습니다.

## 배포 파일로 실행

[GitHub Releases](https://github.com/junhanzang/Chzzk-Bot/releases)에서 `desk-v`로 시작하는 버전의 Windows x64 설치 파일을 내려받거나, Windows ZIP 전체를 압축 해제하고 `Chzzk Desk.exe`를 실행합니다. Node.js나 Python을 따로 설치할 필요가 없습니다. 현재 배포는 코드서명·자동 업데이트가 없는 시험 버전입니다. [배포 과정과 다음 버전 만들기](../docs/RELEASING.md)

## 소스 코드로 실행

Node.js 22 이상이 필요합니다. 처음 한 번 프로젝트 루트에서 실행합니다.

```powershell
cd desktop
npm install
npm start
```

이후 프로젝트 루트의 `start-desk.cmd`를 더블클릭해도 됩니다. 설치 과정에서 Electron과 FFmpeg가 다운로드됩니다. 별도의 Python, Ollama, GPU 설정은 필요하지 않습니다.

## Chrome에서도 사용하기

`browser-extension/` 폴더를 Chrome의 압축해제된 확장 프로그램으로 등록하면 공식 방송 탭 옆에 사이드패널을 열 수 있습니다. [자세한 설치 안내](../browser-extension/README.md)

1. 앱 오른쪽 아래 **크롬과 함께 쓰기 → 연결 코드 복사**를 누릅니다.
2. 확장 사이드패널의 **앱 연결**에 코드를 붙여 넣습니다.
3. 확장에서 채널의 **A / B / C / D**를 눌러 Chrome 공식 방송 탭을 엽니다. 해당 앱 플레이어는 **크롬 시청 모드**로 바뀌며 중복 재생하지 않습니다.
4. 확장 또는 앱에서 **최근 구간 보관**을 켜고 저장 길이(15·30·60초)를 선택한 뒤 저장합니다. 클립은 앱의 동영상 폴더와 양쪽 보관함에서 확인할 수 있습니다.

Chrome만 사용할 때에는 확장 안의 즐겨찾기와 방송 소리 전환을 사용할 수 있습니다. 앱 연결 후에는 앱의 즐겨찾기·시청 자리·보관함을 사용합니다. Chrome의 시청 로그인과 앱의 녹화 로그인은 각각 유지하므로 녹화 권한 오류가 나면 앱의 네이버 로그인 상태도 확인하세요. Chrome 쿠키를 복사하지 않습니다.

연결 코드는 앱을 다시 시작할 때 바뀝니다. 재실행 후 새 코드로 연결하세요. 앱의 **연결 초기화**는 이전 코드를 즉시 무효화합니다. 연결이 끊겨도 이미 앱에서 켠 보관은 앱에서 끄거나 종료할 때까지 계속됩니다. 앱으로 시청을 되돌리려면 해당 자리의 **앱에서 보기**를 누릅니다. 시청 방식을 전환할 때 진행 중인 구간 보관은 종료되며 필요하면 다시 켜야 합니다.

Chrome의 고화질은 네이버 공식 확장 프로그램·커넥터와 방송 설정을 따릅니다. 확장은 화질을 낮추거나 자체 플레이어로 바꾸지 않습니다. **앱 내부 고화질 재생은 여전히 지원하지 않으며, 클립은 앱이 받은 HLS 스트림 기준이므로 Chrome에서 보는 화질과 같다고 보장하지 않습니다.** [네이버 고화질 시청 안내](https://help.naver.com/service/23946/contents/23231?lang=ko&osType=COMMONOS)

앱과 확장은 `127.0.0.1`의 임시 포트로 연결합니다. 연결 코드와 Chrome 확장 출처를 검사하고 정해진 방송·클립 명령만 받습니다. 연결 토큰, 로그인 쿠키, 계정 닉네임은 확장 상태 응답에 포함하지 않습니다. 채널 입력·설정 정리 규칙은 `browser-extension/shared/channels.js`를 두 클라이언트가 공유합니다.

## 사용 흐름

자동 클립은 각 방송의 **자동 저장**을 펼쳐 조건을 설정하고 **적용**하면 됩니다. 기본은 꺼짐이며 **최근 구간 보관**을 따로 켜고 공식 채팅을 열어 두어야 합니다. 감지한 시점의 완료 영상 기준 앞 20초와 뒤 10초를 로컬 MP4로 저장합니다. 채널당 2분 간격·시간당 최대 10회 시도하며, 처음 로드된 채팅 기록은 건너뜁니다. 영상과 채팅 지연·세그먼트 경계에 따라 실제 장면과 길이가 달라질 수 있습니다. [자동 클립의 상세 조건과 검증 범위](../docs/releases/0.4.0.md)

1. 치지직 방송 URL 또는 32자리 채널 ID를 붙여 넣고 즐겨찾기에 추가합니다. 이름은 선택 사항입니다.
2. 즐겨찾기의 **A / B / C / D**로 최대 네 화면에 방송을 배치합니다. 각 화면은 공식 치지직 방송 페이지를 엽니다.
   고화질 확장 프로그램 안내가 뜨면 공식 플레이어의 **설치없이 일반 화질 시청**을 선택하세요. 이 앱은 치지직 고화질 확장 프로그램을 지원하지 않습니다. 광고나 로그인 안내도 공식 페이지에서 처리합니다.
3. **이 방송 듣기**로 소리를 켭니다. 선택한 한 방송만 소리가 나고, **앱 음소거**로 앱 안의 방송 소리를 모두 끌 수 있습니다. Chrome 탭의 소리는 확장에서 제어합니다. 공식 플레이어 자체가 음소거 상태라면 그 플레이어에서도 소리를 켜야 합니다.
4. 저장할 방송에서 **최근 구간 보관**을 켭니다. 저장 길이를 **15·30·60초** 중 선택합니다(기본 30초). 완료된 영상이 4초 이상 쌓이면 최근 구간을 저장할 수 있습니다. 선택한 길이보다 적게 모였다면 확보된 분량만 저장합니다.
5. 아래 클립 보관함에서 저장된 MP4를 열거나 **보관 폴더 열기**로 파일을 확인합니다.

즐겨찾기는 이름·채널 ID로, 클립은 방송 이름·제목·파일명으로 검색할 수 있습니다. 클립은 저장된 인덱스 전체에서 검색하고 50개씩 **더 보기**로 이어 봅니다. 제목 수정·별표 즐겨찾기·저장 유형 필터와 최신순·오래된순 정렬을 지원합니다. 제목 수정은 실제 파일명을 바꾸지 않으며, 개별 **폴더** 버튼은 탐색기에서 파일을 선택합니다. 검색 입력은 상태 갱신 중에도 유지합니다. 저장 길이는 앱을 다시 켜도 유지되고, 앱에 연결한 Chrome에서도 같은 값을 사용합니다.

**시청 모음**에서 현재 A–D 배치와 메인 방송을 최대 10개 저장하고 불러옵니다. 변경되는 자리는 적용 전에 안내하며 해당 자리의 구간 보관은 종료됩니다. 모음은 소리나 보관을 자동으로 켜지 않습니다. **전체 보관 켜기·끄기**로 열린 방송의 보관을 한 번에 조절하고 일부 실패 시 해당 자리를 확인합니다. 즐겨찾기 이름 수정·상단 고정도 양쪽에서 공유합니다. [0.5.0 변경 내용](../docs/releases/0.5.0.md)

**네이버 로그인**은 네이버 공식 로그인 창을 직접 엽니다. 치지직으로 돌아오면 로그인 여부를 확인하고, 성공 시 창을 닫으며 앱의 방송을 새로고침합니다. 상단에는 **로그인됨**을 표시하고 버튼에 마우스를 올리면 닉네임을 확인할 수 있습니다.

첫 사용 때 앱에서 한 번 로그인하면 앱의 방송과 구간 보관에서 같은 세션을 사용합니다. 기존 Python 봇과 같은 웹 로그인 방식이며, 별도 OAuth 앱 등록이나 쿠키 복사는 필요하지 않습니다. 로그인은 앱 전용 브라우저 프로필에 유지하며 기존 봇의 `.env`를 읽거나 변경하지 않습니다. 로그인된 상태에서 버튼을 다시 누르면 치지직 계정 페이지를 열 수 있습니다.

## 화면 배치와 통나무

- **나란히 / 세로 / 4분할 / 메인 크게** 중 배치를 선택하고 메인 방송을 지정할 수 있습니다. 메인 방송 변경은 듣는 방송을 바꾸지 않습니다. 배치와 메인 선택은 저장하며, 앱 연결 중에는 확장과 같은 설정을 사용합니다.
- 앱은 한 창 안에서 방송을 배치합니다. Chrome 확장은 공식 방송 탭을 별도 창으로 배치하며, 확장의 **창 배치**를 눌러 적용합니다. 화질을 강제로 변경하지 않습니다.
- **통나무 자동 수령**은 기본적으로 꺼져 있습니다. 켜면 앱에서 시청 중인 공식 방송의 시청 보상 버튼을 감지해 수령하고 설정을 저장합니다. 보상 상태와 보유량 변화를 확인한 뒤 수령 완료를 표시합니다.
- 자동 수령을 꺼도 보유량은 약 60초 간격으로 조회합니다. 로그인이나 조회 오류로 보유량을 알 수 없으면 0으로 표시하지 않습니다. 앱과 Chrome은 로그인·자동 수령 설정·보유량을 각각 관리합니다.
- 통나무는 여러 방송을 열어도 한 채널의 시청 시간만 인정됩니다. 1시간 시청 보상은 수령 버튼이 생긴 뒤 1시간 내 받아야 합니다. [네이버 통나무 안내](https://help.naver.com/service/30044/contents/24337?lang=ko&osType=COMMONOS)
- 채팅 영역이 접혀 보상 버튼이 없거나 치지직의 화면·응답 구조가 바뀌면 자동 수령이 동작하지 않을 수 있습니다. 현재 가짜 화면·응답 테스트를 통과했으며 실제 계정의 수령은 직접 확인해야 합니다. [구현 근거와 범위](../browser-extension/shared/REWARDS-SOURCES.md)

## 단축키

| 기능 | 앱 화면에 포커스 | 방송·채팅에 포커스 |
| --- | --- | --- |
| A 듣기 | `1` | `Ctrl+Alt+1` |
| B 듣기 | `2` | `Ctrl+Alt+2` |
| C 듣기 | `3` | `Ctrl+Alt+3` |
| D 듣기 | `4` | `Ctrl+Alt+4` |
| 앱 음소거 | `M` | `Ctrl+Alt+M` |
| 최근 구간 저장 | `Ctrl+Shift+S` | `Ctrl+Shift+S` |

앱 화면의 단축키는 입력란을 작성 중일 때 동작하지 않습니다. 방송·채팅에서는 조합키만 처리합니다. 저장 단축키도 선택한 15·30·60초 길이를 사용하며, 저장 대상은 현재 듣는 방송입니다. 전체 음소거 상태에서는 방송 화면 안에서 단축키를 누른 경우 해당 방송을, 앱 화면에서는 마지막으로 선택한 방송을 사용합니다(초기값 A). 앱 밖에서 동작하는 전역 단축키는 아닙니다.

## 저장 방식과 현재 범위

- **보관을 켠 이후**의 영상만 저장할 수 있습니다. 앱을 다시 열면 즐겨찾기와 화면 배치는 복원되지만, 소리와 보관 기능은 꺼진 상태로 시작합니다.
- 방송별 임시 영상은 약 90초와 512MB 한도를 기준으로 정리합니다. 끄거나 채널을 바꾸거나 앱을 종료하면 해당 임시 영상은 삭제합니다. 비정상 종료로 남은 임시 폴더는 다음 실행 때 정리합니다.
- 이미 저장한 MP4는 자동 삭제하지 않습니다. 기본 저장 위치는 Windows의 **동영상 → Chzzk Desk**입니다(보통 `%USERPROFILE%\Videos\Chzzk Desk`). 이전 `userData/clips`의 클립은 다음 실행 때 원본을 유지한 채 새 위치로 복사합니다. 동명 파일은 덮어쓰지 않습니다. 실제 위치는 앱의 **보관 폴더 열기**로 확인할 수 있습니다.
- 선택한 저장 길이는 영상 구간 경계 기준입니다. 15·30·60초보다 조금 길거나, 보관을 막 켰다면 짧을 수 있습니다. 보관함에는 실제 저장 길이를 표시합니다.
- 방송 연결이 끊겨도 완료된 영상이 4초 이상 남아 있으면 마지막 구간을 저장할 수 있습니다. 보관을 다시 켜기 전에 저장하세요.
- 보관 기능은 공식 플레이어와 별도로 HLS 영상을 수신합니다. 보고 있는 화면과 저장 끝점이 몇 초 차이 날 수 있고, 방송별 추가 네트워크·디스크 사용이 발생합니다. 방송 영상만 저장하며 채팅은 포함되지 않습니다.
- 로그인·성인 제한·유료/권한 제한 방송과 플랫폼의 재생 방식에 따라 시청 또는 보관이 실패할 수 있습니다. 공식 페이지의 로그인과 모든 방송의 녹화 호환성을 보장하지 않습니다.
- 보관 준비에는 치지직 웹사이트가 사용하는 비공식 `live-detail` 경로를 사용합니다. 치지직 변경에 따라 수정이 필요할 수 있습니다. 미디어 주소와 쿠키를 앱 로그나 설정에 저장하지 않습니다.
- 방송 정보·영상·암호화 키는 앱의 로그인 세션으로 요청합니다. FFmpeg에는 임시 로컬 주소만 전달하며 쿠키 원문을 명령줄이나 설정 파일에 복사하지 않습니다. 네이버 로그인 쿠키의 전송 대상은 브라우저가 도메인 기준으로 결정합니다.
- 영상 서버가 401/403 또는 암호화 키 접근 실패를 응답하면 보관을 중단하고 접근 거부 오류를 표시합니다. 로그인 후에도 방송별 권한이나 재생 방식에 따라 제한될 수 있습니다.
- 기존 AI 채팅, 자동 클립 선정, 방송 알림, 방송 간 재생 동기화와 다시보기 채팅 검색은 아직 이 앱에 통합하지 않았습니다.

## 개발·검증

[모듈별 책임과 변경 시 확인 사항](ARCHITECTURE.md)을 먼저 확인하세요. `npm run check`는 양쪽 문법 검사와 자동 테스트를 한 번에 실행하며 앱·브라우저 창을 열지 않습니다.

```powershell
npm run check
npm test
npm run test:extension
npm run test:browser-replay
npm run test:clip-lengths
npm run test:smoke
npm run test:replay
npm run test:auth
npm run test:session-replay
```

- `test`: 채널 입력·설정 복구와 녹화 구간 선택, 정리, 취소, 오류 처리, 저장 위치 변경, 실제 경로 전달을 검증합니다. 창이나 외부 재생 앱을 열지 않습니다.
- `test:extension`: 실제 Chrome을 열지 않고 브라우저 API 대역으로 즐겨찾기·탭 관리·음소거·앱 연결과 오류 처리를 검증합니다.
- `test:browser-replay`: 확장 프로그램의 실제 RPC 클라이언트 → 로컬 앱 연결 → FFmpeg 저장 → MP4 영상·음성 디코딩을 검증합니다. 출처 헤더와 방송은 테스트용이며 Chrome/Electron 화면을 실행하지 않습니다.
- `test:clip-lengths`: 같은 합성 방송에서 15·30·60초 설정을 바꿔 RPC 저장과 각 MP4의 영상·음성 디코딩을 확인합니다. 실제 계정이나 앱·브라우저 화면을 사용하지 않습니다.
- `test:smoke`: 별도 프로필과 가짜 방송 페이지로 실제 Electron 창, 음소거, 화면 크기, 즐겨찾기 복원을 검증합니다. 실제 치지직 재생을 검증하는 테스트는 아닙니다.
- `test:replay`: 직접 생성한 HLS 영상에서 MP4를 저장한 뒤 FFmpeg로 영상·음성을 끝까지 디코딩합니다.
- `test:auth`: 별도 Electron 프로필의 가짜 로그인 응답으로 로그인 창·복귀·상태 표시·방송 새로고침을 검증합니다. 실제 네이버 계정 로그인 성공을 뜻하지 않습니다. protocol fixture에서 쿠키 헤더를 관찰하지 못하면 실제 네트워크 쿠키 전송 검증은 SKIP으로 표시합니다.
- `test:session-replay`: 테스트 세션에서 로그인 전 키 요청 403, 로그인 후 AES-128 HLS 수신, 약 30초 MP4 저장과 영상·음성 디코딩을 검증합니다. 실제 네이버 계정은 사용하지 않습니다.

테스트 파일과 프로필은 `desktop/.artifacts/`에 생성하며 Git에서 제외합니다.

### 보관 폴더 또는 클립을 찾을 수 없었던 문제

MSIX 앱에서 개발용 Electron을 실행하면 AppData가 패키지 전용 위치로 연결될 수 있습니다. 이때 앱 내부에서 파일이 보여도, 탐색기나 기본 동영상 앱에 논리 경로를 전달하면 “위치를 사용할 수 없습니다” 또는 `0x80070002`가 발생할 수 있습니다. [Windows AppData 가상화 설명](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes#appdata-operations-on-windows-10-version-1903-and-later)

클립은 동영상 폴더에 저장하고, 외부 앱에 전달하는 경로는 `fs.realpath.native`로 실제 위치를 확인합니다. 앱 프로필도 세션 생성 전에 실제 경로로 정합니다. 기본 프로필이 비어 있고 Codex 패키지 안에 기존 Chzzk Desk 프로필이 하나만 있다면 이를 다시 사용해 로그인·즐겨찾기·보관함을 이어갑니다. 쿠키를 읽어 내보내거나 복사하지 않습니다. `DESK_DATA_DIR`로 지정한 테스트·사용자 프로필은 다른 프로필을 찾지 않으며, 클립도 해당 디렉터리 안에 보관합니다.

앱의 `main.cjs`는 환경 초기화와 서비스 연결을 맡습니다. `lib/desk-controller.cjs`가 설정·사용자 명령, `lib/player-manager.cjs`가 플레이어 수명, `lib/recording-service.cjs`가 녹화·미디어 주소 수명을 소유합니다. 화면은 `ui/renderer.mjs`에서 상태 컨트롤러와 영역별 뷰를 연결하고, `preload.cjs`의 제한된 IPC로 통신합니다. [모듈별 책임과 의존성 규칙](ARCHITECTURE.md)에 구조를 정리했습니다. 원격 치지직 페이지에는 Node.js나 앱의 IPC를 제공하지 않습니다.

미디어 중계는 `127.0.0.1`의 임시 포트에서만 동작합니다. 재생 목록의 경로를 무작위 로컬 주소로 바꾸고, 치지직 CDN 및 지정된 암호화 키 경로만 허용합니다. 방송 보관을 끄거나 종료하면 해당 주소와 요청도 폐기합니다. 상위 요청의 Referer는 Chromium의 기본 요청 정책에 맞춰 치지직 원점만 사용합니다.
