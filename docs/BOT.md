# 채팅 봇 시작하기

이 문서는 방송 소리를 듣고 채팅에 반응하는 Python 봇 안내입니다. 멀티뷰·클립용 앱은 `start-desk.cmd`, 채팅 봇은 **`start-bot.cmd`**로 실행합니다. 두 기능의 로그인과 실행 환경은 별개입니다.

## 가장 빠르게 확인하기

Python 3.11 이상이 설치되어 있다면 프로젝트 폴더에서 `start-bot.cmd`를 더블클릭합니다. 사용 중인 `.venv` 또는 `venv`가 있으면 해당 Python을 먼저 사용합니다. 메뉴의 **3. 모델 없이 동작 데모**는 추가 패키지·로그인·음성 장치·모델 없이 실행됩니다.

```powershell
python main.py --demo
```

데모는 준비된 답변으로 문맥 전달·중복·만료·수정·생략 규칙을 보여줍니다. 실제 AI의 말투와 참여 판단은 아래의 20개 상황 평가와 문장 리플레이로 확인합니다.

## 처음 설정하기

1. [README 설치 가이드](../README.md#설치-가이드)대로 봇 의존성과 Ollama를 준비합니다. 설치나 모델 다운로드를 프로그램이 임의로 실행하지 않습니다.
2. 시작 메뉴의 **1. 처음 설정 / 설정 변경**에서 방송 URL, 반응 모드, 모델, 서버, 출력 장치 ID, 응답 간격을 저장합니다.
3. **2. 실행 환경 진단**을 실행하고 `수정 필요` 항목을 확인합니다.
4. 방송 소리를 재생한 뒤 **4. 방송을 들으며 미리보기**로 반응을 확인합니다. 이 단계는 AI 모드에서 음성·모델을 사용하며, 실제 채팅을 보내지 않습니다.
5. **5. 메시지마다 승인** 또는 **6. 자동 전송**으로 실행합니다. 실제 전송에는 유효한 로그인 쿠키가 필요합니다. 첫 대화형 실행에서는 기존 로그인 절차를 사용할 수 있습니다.

```powershell
python main.py --setup
python main.py --doctor
python main.py --mock --non-interactive
```

설정은 실행한 폴더와 관계없이 프로젝트의 `.env`에서 읽습니다. 설정 마법사는 변경한 항목만 저장하고 기존 쿠키·주석·고급 설정을 보존합니다. 우선순위는 **CLI 옵션 → 프로세스 환경 변수 → 프로젝트 `.env` → 기본값**입니다. 환경 변수가 설정되어 있으면 마법사에서 저장한 값보다 우선합니다.

장치 ID는 `python main.py --list-speakers`로 확인합니다. ID를 저장하면 매번 선택하지 않아도 됩니다. 입력 없이 실행할 때 장치가 비어 있으면 시스템 기본 출력 장치를 사용합니다. 저장한 장치가 없어졌다면 오류를 확인하고 다시 선택하세요. `--doctor`는 장치를 실제로 열거나 모델을 로드하지 않습니다.

## 자주 사용하는 실행 방식

| 목적 | 명령 |
|---|---|
| 메뉴 열기 | `python main.py --menu` |
| 기본 실행, 메시지마다 승인 | `python main.py` |
| 채팅 전송 없이 미리보기 | `python main.py --mock --non-interactive` |
| 저장한 설정으로 자동 실행 | `python main.py --auto --non-interactive` |
| 이번 실행만 다른 방송 선택 | `python main.py --channel https://chzzk.naver.com/live/채널ID` |
| 모델·음성 없이 채팅 분위기만 따라하기 | `python main.py --mode mimic --mock --non-interactive` |
| 사용 가능한 출력 장치 | `python main.py --list-speakers` |
| 모든 옵션 | `python main.py --help` |

`--non-interactive`는 질문이나 브라우저 로그인을 열지 않습니다. 실제 전송에는 `--auto`와 미리 저장한 쿠키가 필요하고, 조건이 부족하면 안내 후 종료합니다. 기본 실행의 승인은 `Enter=전송`, `s=생략`, `e=수정`, `m=모드 전환`입니다. Windows의 대화형 자동 전송에서는 `h`로 연결 상태와 세션 요약을 봅니다. `Ctrl+C`로 종료합니다.

`mimic`은 음성 모델·오디오·Ollama 연결을 생략합니다. 실행 중 AI 모드로 전환할 때 필요한 자원을 준비하며, 준비에 실패하면 현재 모드를 유지합니다. 이미 준비한 음성 자원은 세션 종료 때 정리합니다.

## 20개 상황으로 응답과 생략 판단 평가하기

이미 준비된 Ollama 서버와 모델이 있다면 다음 명령으로 기본 평가를 실행합니다. 방송·음성 장치·로그인 없이 문장만 입력하며, 채팅을 전송하지 않습니다.

```powershell
python main.py --evaluate --report outputs/bot-quality-report.json
```

`examples/bot-quality.json`에는 가상 방송 상황 20개가 들어 있습니다. 응답이 필요한 상황 10개, 생략해야 할 상황 7개, 둘 다 가능한 상황 3개로 구성했습니다. 짧은 후속 질문, 주제 전환, 혼잣말, 집중 요청, 공감, 화면 정보 부족, 미확인 채팅, 최근 보낸 답변 등을 확인합니다. 각 상황의 이전 발화·채팅·전송 이력은 독립적이며, 앞 상황에서 생성한 초안을 다음 상황의 실제 전송 이력으로 넣지 않습니다.

모델이 없거나 서버에 연결할 수 없으면 자동 설치·다운로드 없이 종료 코드 `2`로 종료하고 **미측정 보고서**를 저장합니다. 이때 `evaluation_status`는 `unavailable`, `actual_model_measured`는 `false`, 선택 일치율은 `null`입니다. 모델 없는 데모가 통과해도 실제 모델 품질이 검증된 것은 아닙니다.

| 생성 상태 | 의미 | 선택 일치로 인정 |
|---|---|---|
| `generated` | 형식·응답 가드를 통과한 답변 | 응답 또는 둘 다 허용인 상황 |
| `skipped` | 모델이 명시적으로 `[SKIP]` 선택 | 생략 또는 둘 다 허용인 상황 |
| `filtered` | 형식·금칙어·반복·출력 토큰 한도 등으로 차단 | 인정하지 않음 |
| `error` | 연결·시간 초과·서버·응답 데이터 오류 | 인정하지 않음 |

보고서는 원문 응답, 처리 사유, 생성 시간, 상황별 검토 기준을 담고 매 상황이 끝날 때 저장됩니다. `Ctrl+C`로 중단해도 완료된 결과가 남습니다. 선택 일치율의 분모는 전체 상황 수이므로 미실행 상황이 통과로 계산되지 않습니다. 전부 선택이 일치하면 종료 코드 `0`, 불일치·필터·생성 오류가 있으면 `1`, 중단하면 `130`입니다.

선택 일치율은 **답할지 생략할지**만 평가합니다. 자연스러운 말투, 사실성, 맥락 이해는 보고서의 `review_rubric`과 실제 응답을 함께 읽어 판단해야 합니다. 이 평가는 실전의 확률·채팅 속도별 응답 간격·음성 인식·동시 처리까지 재현하지 않습니다.

보고서에는 모델 이름·가능한 경우 모델 식별값과 Ollama 버전·프롬프트와 평가 파일의 해시·실제 생성 옵션을 기록합니다. 평가는 `seed=0`을 사용하지만 하드웨어나 서버 버전이 달라지면 같은 결과를 보장하지 않습니다. 기본 모델 설정을 바꾸지 않고 이미 준비된 다른 모델을 비교하거나 별도 상황 파일을 사용할 수도 있습니다.

```powershell
python main.py --evaluate --model 모델이름:태그 --report outputs/bot-quality-other.json
python main.py --evaluate examples/bot-quality.json --report outputs/bot-quality-repeat.json
```

## 문장으로 AI 반응 점검하기

방송·로그인·마이크 없이, 문장과 앞뒤 맥락을 Ollama에 넣어 응답을 확인할 수 있습니다.

```powershell
python main.py --replay examples/bot-demo.json --generate --report outputs/bot-review.json
```

`--generate`가 있을 때만 모델에 요청합니다. 없으면 JSON의 `draft`를 사용해 규칙을 재현합니다. 양쪽 모두 채팅에 연결하거나 전송하지 않고, 실제 채널의 장기 기억을 수정하지 않습니다. 보고서는 지정했을 때만 저장하며 입력 문장·직전 맥락·응답·처리 결과·생성 시간을 담습니다.

```json
{
  "version": 1,
  "events": [
    {"at": 0, "speech": "첫 번째 상자는 이미 열었어", "draft": "[SKIP]"},
    {"at": 2, "speech": "그 다음은?", "draft": "두 번째 상자도 궁금하네"}
  ]
}
```

`at`은 시작 후 발화가 발생한 초이며 순서대로 작성합니다. `speech`는 필수이고 `chat`으로 채팅 맥락을 추가할 수 있습니다. `delay`는 대기시간을 잠들지 않고 모의합니다. `action: "skip"` 또는 `action: "edit"`와 `edit` 문장으로 승인을 재현합니다. `expected`는 준비된 답변 검사에서만 사용하며 `accepted`, `expired`, `cooldown`, `skipped`, `filtered`를 지원합니다. `accepted`는 전송 가능한 상태라는 뜻이며 실제 메시지 수는 언제나 0입니다. 파일은 1 MiB·최대 1000개 발화까지 지원합니다.

실제 생성 시간도 발화 유효시간에 포함합니다. 모델이 느려 이전 발화가 만료되면 다음 입력에도 지연이 이어집니다. 이 기능은 순차 처리 점검이며 음성 인식·동시 채팅 연결까지 재현하지 않습니다. 실제 모델의 정상 생략은 `skipped`, 차단은 `filtered`, 생성 실패는 `error`로 구분하며 생성 오류가 있으면 종료 코드 `1`을 반환합니다. 최종 결과가 만료여도 원래 생성 상태·사유는 별도로 남깁니다.

확인할 품질 기준은 짧은 후속 질문의 맥락, 보지 못한 화면에 대한 추측, 어색한 반복, 끼어들 필요가 없는 순간의 생략입니다. 통과율만으로 자연스러움을 단정하지 말고 보고서의 문장과 응답을 함께 확인하세요.

실전 AI 반응에서는 참여 여부와 답변을 같은 맥락을 넣은 한 번의 요청으로 판단합니다. `SMART_RESPONSE=true`는 이 요청 안에서 참여 기준을 더 엄격하게 적용합니다. 문맥을 준비한 시간도 발화 유효시간에서 빼고 남은 시간을 요청 제한시간에 반영하며, 생성 후와 전송 직전에도 만료 여부를 확인합니다.

## 문제가 생겼을 때

- **설정 오류:** 항목명과 허용 범위를 함께 안내합니다. `.env`를 수정하거나 `--setup`을 사용하세요. 모델 이름은 정확한 태그까지 맞아야 합니다.
- **미리보기가 조용함:** 모드·응답 간격·유효시간을 확인하고 종료 후 세션 요약의 만료·필터·오류 개수를 보세요. 채팅 따라하기는 반응이 몰릴 때만 제안합니다.
- **로그인 실패:** 입력 없는 실행은 자동 로그인 창을 열지 않습니다. 대화형으로 다시 로그인한 뒤 자동 실행하세요.
- **네트워크 단절:** 채팅 연결은 점차 간격을 늘려 재접속합니다. 불확실하게 실패한 채팅 전송은 중복 방지를 위해 자동 재전송하지 않습니다.
- **중간 종료/초기화 실패:** 시작한 자원을 정리하고 전송 대기열을 닫습니다. 같은 프로세스에서 새 세션을 만들거나 명령을 다시 실행하세요.

세션 요약은 원문·쿠키를 저장하지 않는 메모리 내 카운터입니다. 실제 사용 중 채널 기억은 기존 `data/채널ID/`에 유지하고, Mock 기억은 `data/mock/채널ID/`에 분리합니다. 리플레이·평가 보고서에는 입력 문장과 모델 응답이 들어갑니다.

## 봇 소스 배포

```powershell
python build_dist.py
```

`release/chzzk-bot-source.zip`과 SHA-256 파일을 만듭니다. 소스·시작 메뉴·설정 예제·문서만 담으며 실제 `.env`, 채널 기억, 모델, 가상환경은 제외합니다. Python과 런타임 의존성은 별도로 설치해야 합니다. CI는 Windows와 Linux에서 테스트 후 ZIP을 풀어 추가 패키지 없이 데모가 실행되는지도 확인합니다. 소스 ZIP의 생성은 GitHub Release 공개와 별개입니다.
